# 센서 패키지 설명서

센서 패키지는 방 밝기, 소리, 온도, 화면 빛, 폰 거치대, 물병, 심박을 재서 **사실만** `facts`에 적고, 한 번 일어난 일은 이벤트로 넣어요. "춥다", "밤샘이다" 같은 판단은 하지 않아요. 판단은 펫 모듈이 해요.

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `Sensors.cpp` | `Sensors::setup()` / `Sensors::update()`가 아래 센서들을 차례로 불러요 |
| `SensorsConfig.h` | 기준값, 측정 간격, 보정값을 전부 모아 둔 곳이에요. 숫자를 바꿀 때는 여기만 고쳐요 |
| `SensorAdc.h` | 아날로그 읽기 도우미예요. `readSettled()`는 한 번 버리고 다시 읽어요 (아래 "ADC 공유" 참고) |
| `SensorLight.h/.cpp` | 방 조도 (CdS) |
| `SensorNoise.h/.cpp` | 밤 소음 (소리 센서) |
| `SensorTemp.h/.cpp` | 방 온도 (LM35) |
| `SensorBlueLed.h/.cpp` | 소등 후 화면 빛 (파란 LED를 빛 센서로 사용) |
| `SensorPhone.h/.cpp` | 폰 거치대 (압력 센서 + 피에조 진동) |
| `SensorWater.h/.cpp` | 물병 수위 (호일 + CapacitiveSensor 라이브러리) |
| `SensorPulse.h/.cpp` | 심박 (펄스 센서) |
| `firmware/tests/<이름>/<이름>.ino` | 센서 하나만 연결해서 값을 시리얼로 보는 시험용 스케치예요 |

## 공통으로 알아 둘 것

- **5V와 GND:** 모든 센서는 Mega의 5V와 GND를 써요. 빨간 선 = 5V, 검은 선 = GND로 통일해요.
- **`delay()` 없음:** 모든 측정은 `millis()`/`micros()`로 시간을 재고, 오래 걸리는 측정은 여러 `loop()`에 나눠서 해요.
- **ADC 공유:** Mega는 아날로그 값을 재는 장치(ADC)가 하나뿐이고, 핀을 바꿔 가며 써요. CdS·압력 센서·피에조처럼 저항이 큰 센서는 핀을 바꾼 직전 값이 조금 남아 있어서, **한 번 읽어 버리고 다시 읽어요** (`SensorAdc::readSettled()`). 소리 센서, LM35, 펄스 센서는 출력이 강해서 바로 읽어요.
- **loop 속도:** OLED 화면을 그리는 동안은 센서를 읽지 못해요. 그래서 소리와 피에조는 한 번 부를 때 여러 번(8번, 약 1 ms) 몰아서 읽고, 심박은 `Sensors::update()`의 처음과 끝에 두 번 불러서 2 ms 간격에 최대한 가깝게 읽어요. loop가 느리면 파란 LED 측정의 정밀도도 loop 한 바퀴 시간만큼 떨어져요.
- **시험용 스케치:** `firmware/tests/` 아래 스케치는 핀 번호를 직접 적어 두었어요 (`Pins.h`와 같은 번호예요). Arduino IDE에서 열어 업로드하고, 시리얼 모니터나 **시리얼 플로터**를 **115200 baud**로 열어 값을 봐요.

## 센서가 채우는 값

| 값 | 뜻 | 센서 |
|---|---|---|
| `facts.lightRaw` | 부드럽게 만든 밝기 값 (0~1023, 밝을수록 큼) | CdS |
| `facts.roomDark` | 방이 어두운지 | CdS |
| `facts.noiseLevel` | 지금 소리 크기 0~100 (상대값, dB 아님) | 소리 센서 |
| `facts.roomTempC`, `facts.tempValid` | 방 온도(℃), 값이 믿을 만한지 | LM35 |
| `facts.screenGlow` | 파란 LED가 빛을 받는지 | 파란 LED |
| `facts.phonePresent` | 폰이 거치대에 있는지 | 압력 센서 |
| `facts.bottlePresent`, `facts.waterPercent`, `facts.waterValid` | 물병이 있는지, 물 양(%), 그 값이 믿을 만한지 | 호일 |
| `facts.fingerOn`, `facts.heartBpm`, `facts.heartValid` | 손가락에서 맥박이 잡히는지, 심박수, 안정된 값인지 | 펄스 센서 |

| 이벤트 | 언제 | 값 |
|---|---|---|
| `Ev::LoudNoise` | 큰 소리 (박수 한 번 = 이벤트 한 번) | 그때 소리 크기 0~100 |
| `Ev::PhonePlaced` / `Ev::PhoneLifted` | 폰을 올림 / 듦 | 0 |
| `Ev::PhoneBuzz` | 거치대 위 폰이 알림 진동 | 0 |
| `Ev::Drank` | 물병을 들었다 놓았는데 물이 줄었음 | 줄어든 % |

## 1. 방 조도 — CdS (A2)

**무엇을 재나요:** 방 전체의 밝기예요. 불을 끄면 값이 작아져요.

**배선:**
- CdS 한쪽 다리 → **5V**
- CdS 다른 쪽 다리 → **A2**, 그리고 같은 줄에서 **10 kΩ 저항** → **GND**
- 이렇게 하면 밝을수록 A2 값이 커져요 (수업 때 한 CdS 분압 회로와 같아요).

**놓는 곳:** 케이스 뚜껑 위, 천장 쪽을 보게 해요. 모니터 빛이 바로 들어오지 않는 방향이 좋아요.

**동작:** 0.1초마다 읽고 부드럽게 만들어 `lightRaw`에 넣어요. `LIGHT_DARK_BELOW`보다 작아지면 `roomDark = true`, `LIGHT_BRIGHT_ABOVE`보다 커지면 `false`예요. 두 기준 사이에서는 바뀌지 않아서(히스테리시스) 깜빡거리지 않아요. 불을 끄면 1초 안쪽으로 반영돼요.

**혼자 시험:** `tests/light_test` → `light:` 값이 나와요.

**보정:**
1. 불 켠 방, 불 끈 방(모니터만 켠 상태 포함)에서 값을 적어요.
2. 두 값 사이에 `LIGHT_DARK_BELOW`(어둡다고 볼 값)와 그보다 조금 큰 `LIGHT_BRIGHT_ABOVE`를 정해요. 둘 사이 간격은 50~100 정도가 좋아요.

**주의:** 시연장 조명은 집보다 훨씬 밝을 수 있어요. 시연 전에 그 자리에서 값을 다시 확인해요.

## 2. 밤 소음 — 소리 센서 모듈 LM386 (A0)

**무엇을 재나요:** 소리의 **상대적인 크기**예요. dB가 아니에요.

**배선:**
- 모듈 **VCC → 5V**, **GND → GND**, **AO(아날로그 출력) → A0**
- DO(디지털 출력) 핀이 있으면 쓰지 않아요.

**놓는 곳:** **케이스 밖**에 두어요. 케이스 안에 넣으면 소리가 막히고, 펫 소리용 피에조와 너무 가까워져요. 마이크 구멍을 침대 쪽으로 향하게 해요.

**동작:**
- `loop()`마다 8번 몰아서 읽고, 50 ms 동안의 최댓값 − 최솟값(peak-to-peak)을 구해요.
- 이 값을 `SOUND_QUIET_P2P`(조용함 = 0) ~ `SOUND_MAX_P2P`(아주 큼 = 100) 사이로 바꿔 `noiseLevel`에 넣어요. 커질 때는 바로 올라가고, 작아질 때는 50 ms마다 `SOUND_RELEASE_PER_WINDOW`씩 천천히 내려가요.
- 크기가 `SOUND_LOUD_LEVEL` 이상이면 `Ev::LoudNoise`를 넣어요. 한 번 넣으면 `SOUND_EVENT_GAP_MS`(1.5초) 동안은 다시 넣지 않아서, 박수 한 번이 이벤트 한 번이 돼요.
- **펫 소리 무시:** `Sound::busy()`가 참인 동안과 끝난 뒤 `SOUND_AFTER_BUSY_MS`(0.3초) 동안은 아예 재지 않아요. 펫이 낸 소리를 소음으로 세지 않기 위해서예요.

**혼자 시험:** `tests/noise_test` → `min`, `max`, `p2p`가 나와요. 시리얼 플로터로 보면 편해요.

**보정:**
1. **모듈의 파란 가변저항(pot)부터 맞춰요.** 조용할 때 `min`/`max`가 0이나 1023에 붙어 있으면 안 되고, 가운데(약 300~700) 근처에 있어야 해요. 박수를 쳤을 때 `p2p`가 확실히 커지도록 드라이버로 조금씩 돌려요.
2. 조용한 방의 `p2p`보다 조금 크게 `SOUND_QUIET_P2P`를 정해요.
3. 가까이서 큰 박수를 쳤을 때의 `p2p`를 `SOUND_MAX_P2P`로 정해요.
4. "큰 소리"로 세고 싶은 소리를 냈을 때의 크기(0~100)를 보고 `SOUND_LOUD_LEVEL`을 정해요.

**주의:** 값이 소리를 따라 움직이지 않으면 pot이 끝까지 돌아가 있을 가능성이 커요. 이 모듈은 큰 소리에 잘 반응하고 작은 소리 차이는 잘 못 잡아요.

## 3. 방 온도 — LM35 (A1)

**무엇을 재나요:** 방 온도(℃)예요. 계산식은 **℃ = mV ÷ 10**이에요.

**배선:** 글자가 쓰인 평평한 면을 나를 보게 들고, 왼쪽부터
- 왼쪽 다리 **+Vs → 5V**
- 가운데 다리 **Vout → A1**
- 오른쪽 다리 **GND → GND**
- 반대로 꽂으면 아주 뜨거워져요. 처음 켰을 때 만져 보고 뜨거우면 바로 USB를 빼요.

**놓는 곳:** **케이스 밖**에 두어요. 케이스 안은 Mega 열 때문에 실제보다 높게 나와요. 짧은 점퍼선으로 케이스 옆에 세워 두면 시연 때 얼음팩을 대기 쉬워요.

**동작:** 0.5초마다 16번 읽어 평균을 내고, 이전 값과 반씩 섞어요(`TEMP_SMOOTHING = 0.5`). 너무 많이 부드럽게 하지 않아서 얼음팩을 대면 **2~3초 안에** 값이 내려가요. 계산한 온도가 `TEMP_VALID_MIN_C`~`TEMP_VALID_MAX_C`(1~60℃) 밖이면 선이 빠졌다고 보고 `tempValid = false`로 해요.

**혼자 시험:** `tests/temp_test` → `raw`, `mV`, `C`가 나와요. 실내에서 20~28℃ 근처면 정상이에요.

**보정:** 온도계와 비교해서 차이가 크면 `TEMP_ADC_REF_MV`를 조절해요. USB 전원은 정확히 5.0 V가 아닐 때가 많아요(4.7~5.1 V). 멀티미터로 5V 핀 전압을 재서 mV 단위로 적으면 가장 정확해요. 반응을 더 빠르게 하려면 `TEMP_SMOOTHING`을 키우고(최대 1.0), 값이 흔들리면 줄여요.

**주의:**
- **얼음팩은 꼭 천이나 비닐로 감싸요.** 얼음이 직접 닿으면 LM35 다리에 물방울(결로)이 맺혀 값이 엉뚱하게 튀거나 합선될 수 있어요.
- 손으로 오래 잡고 있으면 체온 때문에 올라가요.
- 5V 기준이라 한 칸이 약 0.5℃예요. 16번 평균으로 조금 부드럽게 만들었어요.

## 4. 소등 후 화면 빛 — 파란 LED를 빛 센서로 (D30, D31)

**무엇을 재나요:** 파란 LED에 빛이 들어오는지예요. 소등 후 침대에서 폰·모니터 화면을 켜면 파란빛이 나오는 것을 이용해요. **"화면 빛이 감지됨"까지만 약속해요.** 흰색 LED 조명도 파란빛을 내므로 조명과 화면은 구분하지 못해요.

**원리:** LED에 거꾸로 전압을 걸면(역바이어스) 작은 축전기처럼 전기가 차요. 그 뒤 핀을 입력으로 바꾸면 빛을 받은 만큼 전기가 빠져나가서, **빛이 많을수록 빨리 LOW가 돼요.** 그 시간을 재요.

**배선:**
- 투명한 파란 LED의 **긴 다리(애노드) → 220 Ω 저항 → D30**
- **짧은 다리(캐소드) → D31**
- 5V, GND는 쓰지 않아요. 저항은 실수로 LED가 켜지는 상황을 막는 보호용이에요 (측정에는 영향이 거의 없어요).

**놓는 곳:**
- 케이스 밖, **침대 머리맡(화면을 볼 자리) 쪽을 향하게** 두어요.
- **짧고 어두운 통**(검은 테이프를 감은 빨대나 검은 종이를 말아 2~3 cm) 안에 넣어서 앞쪽 빛만 받게 해요. 방 조명이 옆에서 들어오면 늘 "밝음"으로 꽉 차 버려요.

**동작:**
- 1초마다 측정을 시작해요: 애노드 LOW, 캐소드 HIGH로 잠깐 충전 → 캐소드를 입력(풀업 없음)으로 바꾸고 시각을 기록해요.
- 그다음 `loop()`마다 캐소드가 LOW가 되었는지 확인해요. 기다리지 않고 바로 다음 일로 넘어가요.
- `BLUE_TIMEOUT_US`(0.9초)까지 LOW가 안 되면 "어둡다"로 봐요.
- 걸린 시간이 `BLUE_GLOW_ON_US`보다 짧으면 `screenGlow = true`, `BLUE_GLOW_OFF_US`보다 길면 `false`예요.
- 방 불이 켜져 있어도 `screenGlow`는 참이 될 수 있어요. "소등 **후**"인지는 펫 모듈이 `roomDark`와 함께 판단해요.

**혼자 시험:** `tests/blueled_test` → 1초마다 `discharge_us`가 나와요. 어두우면 `(timeout = dark)`가 붙어요.

**보정:**
1. 방 불을 끄고, LED 앞에 아무것도 없을 때 값(대부분 timeout)을 적어요.
2. 실제 자리에서 폰 화면을 켜고 LED 쪽으로 향했을 때 값을 적어요.
3. 두 값 사이에 `BLUE_GLOW_ON_US`를 정하고, `BLUE_GLOW_OFF_US`는 그보다 조금 길게 정해요.
4. 화면 빛이 약해서 0.9초 안에 LOW가 안 되면 `BLUE_TIMEOUT_US`를 늘려요. 이때 `BLUE_INTERVAL_MS`도 timeout보다 길게 함께 늘려요.

**주의:** 반드시 **투명 렌즈** LED를 써요 (색 렌즈는 둔해요). 시험용 스케치는 loop가 빨라서 시간을 정밀하게 재지만, 본 스케치에서는 OLED 때문에 loop가 느려 수십 ms 단위로 재져요. 기준값은 수십 ms 차이에 의존하지 않게 넉넉히 잡아요.

## 5. 폰 거치대 — 압력 센서 KS0309 (A4) + 피에조 진동 (A5)

**무엇을 재나요:** 폰이 거치대에 놓였는지(압력)와, 놓인 폰이 알림 진동을 했는지(피에조)예요.

**배선 (압력 센서 모듈 keyestudio KS0309):**
- 모듈 **S(신호) → A4**, **V(+) → 5V**, **G(−) → GND**

**배선 (피에조 진동 센서, 키트의 두 번째 수동 피에조):**
- 피에조 **빨간 선 → A5**, **검은 선 → GND**
- **1 MΩ 저항을 A5와 GND 사이**에 꽂아요 (피에조와 나란히, 병렬). 피에조에 쌓인 전기를 빼 주는 역할이에요. 없으면 값이 붙어서 안 내려와요.

**놓는 곳:**
- 압력 센서의 동그란 감지 부분을 **폰 받침판 바로 아래 가운데**에 두어요. 폰 무게가 감지 부분에 실리도록, 받침판과 센서 사이에 작은 고무 발이나 동전을 하나 끼우면 좋아요.
- 피에조 원판은 **받침판 밑면에 글루건으로 붙여요.** 원판 전체가 판에 닿게 붙여야 진동이 잘 전달돼요.
- 거치대는 케이스 밖, 책상 위에 둬요.

**동작 (압력):**
- 0.05초마다 읽고 부드럽게 만들어요.
- `FSR_ON_ABOVE`보다 크면 "눌림", `FSR_OFF_BELOW`보다 작으면 "안 눌림"이에요(히스테리시스).
- 바뀐 상태가 `FSR_DEBOUNCE_MS`(0.3초) 동안 유지되어야 `phonePresent`를 바꾸고 `Ev::PhonePlaced` / `Ev::PhoneLifted`를 넣어요.
- 켤 때 폰이 이미 올려져 있으면, 켜고 약 0.3초 뒤 `PhonePlaced`가 한 번 들어가요.

**동작 (피에조):**
- 폰이 놓여 있을 때만 재요. `loop()`마다 8번 몰아서 읽고, `PIEZO_SPIKE_RAW` 이상이면 "튐" 한 번이에요. 튐은 `PIEZO_SPIKE_GAP_MS`(25 ms) 간격 이상일 때만 따로 세요.
- `PIEZO_WINDOW_MS`(0.8초) 안에 튐이 `PIEZO_MIN_SPIKES`(6번) 이상이면 진동으로 보고 `Ev::PhoneBuzz`를 넣어요. 책상을 한 번 톡 치는 것은 튐이 몇 번 안 돼서 진동으로 세지 않아요.
- 한 번 넣으면 `PIEZO_BUZZ_GAP_MS`(4초) 동안은 다시 넣지 않아요.
- **무시하는 때:** 폰을 올리거나 들면 판이 흔들리므로, 압력 상태가 바뀐 뒤 `PIEZO_IGNORE_AFTER_FSR_MS`(1.5초) 동안은 무시해요. `Sound::busy()`인 동안과 그 뒤 0.3초도 무시해요.

**혼자 시험:** `tests/phone_test` → 0.05초마다 `fsr`과 그동안의 `piezoMax`가 나와요.

**보정:**
1. 폰이 없을 때와 있을 때 `fsr` 값을 적어요. 그 사이에 `FSR_OFF_BELOW`(작은 값)와 `FSR_ON_ABOVE`(큰 값)를 정해요.
2. 폰을 올렸는데 값이 오히려 **작아지면** `FSR_HIGHER_MEANS_PRESSED`를 `false`로 바꿔요. (그러면 코드 안에서 1023 − 값으로 뒤집어서 써요. 기준값도 뒤집힌 값 기준으로 정해요.)
3. 폰을 올려 두고 가만히 있을 때 `piezoMax`, 폰에 진동 알림을 보냈을 때 `piezoMax`를 적어요. 그 사이에 `PIEZO_SPIKE_RAW`를 정해요.
4. 진동인데 이벤트가 안 나오면 `PIEZO_MIN_SPIKES`를 줄이고, 책상만 쳐도 나오면 늘려요.

**주의:** 폰 케이스가 두꺼우면 진동이 약하게 전달돼요. 진동이 너무 약하면 받침판을 얇고 단단한 판(아크릴, 플라스틱 뚜껑)으로 바꿔요.

## 6. 물병 수위 — 알루미늄 호일 두 장 + CapacitiveSensor (D32, D33)

**무엇을 재나요:** 물병 안의 물 양(%)이에요. 물이 많을수록 호일 사이의 정전용량이 커지는 것을 이용해요.

**배선:**
- **D32(보내는 핀) → 1 MΩ 저항 → D33(받는 핀)**
- **D33 → 호일 1** (악어집게 선이나 점퍼선 끝을 호일에 테이프로 꽉 붙여요)
- **호일 2 → GND**
- 라이브러리: Paul Stoffregen의 **CapacitiveSensor** (이미 설치되어 있어요).

**놓는 곳:**
- 물병 받침(컵 홀더) **안쪽 벽 양옆에 호일 띠를 마주 보게** 붙여요. 두 호일이 서로 닿으면 안 돼요.
- 띠는 세로로 길게, 물병 바닥부터 위까지 붙여야 물 높이에 따라 값이 달라져요.
- 호일 위에 투명 테이프를 덮어 손이 직접 닿지 않게 해요.
- 호일에 연결한 선은 짧게 하고, 움직이지 않게 테이프로 고정해요. 선이 흔들리면 값도 흔들려요.

**동작:**
- 0.5초마다 `capacitiveSensorRaw(10)`으로 한 번 재요 (보통 몇 ms 이내).
- **자동 보정은 껐어요** (`set_CS_AutocaL_Millis(0xFFFFFFFF)`). 켜 두면 물이 천천히 줄어드는 변화를 라이브러리가 "기준"으로 지워 버려요. 같은 이유로 기준값을 빼는 `capacitiveSensor()` 대신 **원래 값을 그대로 주는 `capacitiveSensorRaw()`**를 써요.
- 시간 초과(`WATER_TIMEOUT_MS`)나 `WATER_TOUCH_RAW` 이상이면 **손이 닿은 것**으로 보고 그 값은 버려요.
- `WATER_PRESENT_ABOVE`보다 크면 `bottlePresent = true`, `WATER_ABSENT_BELOW`보다 작으면 `false`예요.
- 최근 4번(2초) 값의 차이가 `WATER_STABLE_SPREAD` 이하일 때만 "안정"으로 보고, 그 평균을 `WATER_EMPTY_RAW`(0%) ~ `WATER_FULL_RAW`(100%) 사이로 바꿔 `waterPercent`에 넣고 `waterValid = true`로 해요. 안정되지 않으면 `waterValid = false`이고 `waterPercent`는 마지막 값을 유지해요.
- **마심 감지:** 물병이 사라졌다가(들어 올림) 다시 놓이고 안정된 첫 값이, 들기 전 값보다 `WATER_DRANK_MIN_DROP`(5%) 이상 적으면 `Ev::Drank`를 넣어요. 값은 줄어든 %예요. 물을 다시 채운 경우(늘어남)는 이벤트가 없어요.

**혼자 시험:** `tests/water_test` → 0.5초마다 `water_raw`가 나와요. `-2`는 시간 초과예요 (배선 확인).

**보정:**
1. 물병 없이 → `WATER_ABSENT_BELOW`, `WATER_PRESENT_ABOVE`는 이 값보다 조금 크게 정해요.
2. **빈 물병**을 놓고 → `WATER_EMPTY_RAW`
3. **가득 찬 물병**을 놓고 → `WATER_FULL_RAW`
4. 물병을 손으로 잡고 → 그보다 조금 작게 `WATER_TOUCH_RAW`
5. 가만히 둘 때 값이 흔들리는 폭보다 조금 크게 `WATER_STABLE_SPREAD`
6. 보정한 뒤에는 **호일과 선 위치를 움직이지 않아요.** 움직이면 다시 보정해야 해요.

**주의:**
- 빈 플라스틱 병은 정전용량이 거의 안 바뀌어서 **"병 없음"과 구분이 잘 안 될 수 있어요.** 이 경우 빈 병은 `bottlePresent = false`로 보여요. 시연은 물이 어느 정도 든 병으로 해요.
- USB 노트북이 충전기에 꽂혀 있는지에 따라 값이 달라질 수 있어요. 시연과 같은 상태에서 보정해요.
- 사람이 가까이 오기만 해도 값이 조금 올라가요.

## 7. 심박 — 펄스 센서 SZH-HWS008 (A6)

**무엇을 재나요:** 손가락 끝의 맥박으로 심박수(BPM)를 재요. 운동 전후 비교에 써요.

**배선:**
- 센서 **+ (빨강) → 5V**, **− (검정) → GND**, **S (보라/신호) → A6**

**놓는 곳:** 케이스 밖, 손가락을 편하게 올릴 수 있는 곳이에요. 센서 앞면(하트 그림)에 손가락 끝을 **가볍게** 대요. 세게 누르면 피가 안 통해 맥박이 약해져요. 뒷면 부품이 손에 닿으면 값이 흔들리니 뒷면에 테이프를 붙여 두면 좋아요.

**동작:**
- `micros()`로 약 2 ms마다 한 번 읽어요 (loop가 느리면 그보다 드물어져요).
- **적응형 기준선:** 신호가 기준선을 아래에서 위로 넘으면 "박동 시작", 다시 기준선 − `PULSE_FALL_MARGIN` 아래로 내려가면 "박동 끝"이에요. 박동이 끝날 때마다 그 사이의 최고점·최저점 가운데로 기준선을 옮겨요.
- 최고점 − 최저점이 `PULSE_MIN_AMPLITUDE`보다 작으면 잡음으로 보고 버려요.
- 박동 사이 간격은 `PULSE_MIN_IBI_MS`(0.3초, 200 BPM)보다 길어야 하고, `PULSE_MAX_IBI_MS`(2초, 30 BPM) 동안 박동이 없으면 처음부터 다시 찾아요.
- 최근 5번 간격의 평균으로 `heartBpm = 60000 ÷ 평균 간격(ms)`을 계산해요.
- `fingerOn`은 "최근 2초 안에 제대로 된 박동이 잡혔다"는 뜻이에요.
- `heartValid`는 5번 간격이 모두 모였고, 모두 평균의 ±`PULSE_STABLE_PERCENT`(20%) 안일 때만 참이에요. 손가락을 올리고 **약 5~7초** 뒤에 참이 돼요. 펫은 `heartValid`가 참일 때의 `heartBpm`만 쓰는 게 좋아요.

**혼자 시험:** `tests/pulse_test` → **시리얼 플로터**로 `pulse` 파형을 봐요. 손가락을 올리면 심장 뛰는 모양의 물결이 보여야 해요.

**보정:**
- 파형의 높이(최고 − 최저)가 보통 몇십 이상이에요. 맥박인데 버려지면 `PULSE_MIN_AMPLITUDE`를 줄이고, 손가락이 없는데 박동이 잡히면 늘려요.
- 기준선 근처에서 잡음 때문에 박동이 둘로 쪼개지면 `PULSE_FALL_MARGIN`을 늘려요.
- 운동 직후 심박이 빠르게 변하면 `heartValid`가 늦게 참이 될 수 있어요. 그러면 `PULSE_STABLE_PERCENT`를 조금 늘려요.

**주의:** 형광등이나 햇빛이 센서에 들어가면 잡음이 커져요. 손가락으로 센서를 완전히 덮어요. 손이 차가우면 맥박이 약하게 잡혀요.
